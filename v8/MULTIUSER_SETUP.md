# МАГА v8 — два пользователя, общий каталог и личные данные

**Статус:** тестовая версия. Полная авторизация потребует настройки Supabase. Основной сайт v7 не заменён.

## Как это устроено
- Один публичный каталог из 38 программ, Erasmus и «Болашак» доступен обоим участникам.
- У каждого свой академический профиль, заметки, статусы заявок, задачи, документы и рекомендатели.
- Supabase Auth отправляет ссылку на вход на приглашённый email.
- Политики Row Level Security в Postgres привязывают все личные данные к `auth.uid()`. Два приглашённых участника не видят записи друг друга.
- Данные другого участника нельзя получить простым переключением кнопки в HTML: это разрешает или запрещает сервер.

## Запуск
1. Создайте **отдельный проект Supabase**. Не используйте старый/чужой проект без проверки.
2. Запустите [schema.sql](schema.sql) через SQL Editor, затем проверьте Row Level Security.
3. В Authentication → URL Configuration добавьте Site URL и Redirect URL: `https://55aiai.github.io/masters-2027-dashboard/v8/`.
4. В Authentication → Users пригласите **два** email-адреса. Запретите публичную регистрацию, оставьте invite-only.
5. После приглашения выполните две административные INSERT-команды в комментариях конца SQL, указав реальные email только в приватном SQL Editor. Поле `slot` допускает лишь 1 и 2.
6. В [config.js](config.js) укажите Supabase Project URL и **publishable key** (не secret/service-role key).
7. Откройте [тестовую версию v8](https://55aiai.github.io/masters-2027-dashboard/v8/). Оба участника входят по собственным email.
8. После проверки двух реальных аккаунтов можно обсуждать замену основного `index.html`. До этого оставляем v7 работающим.

## Перенос данных
- Старый v7 содержит персональные сведения первого участника. В v8 они **не опубликованы** в HTML.
- Первый участник импортирует свой отдельный личный JSON-файл в разделе «Синхронизация», **только после входа**.
- Если в старом браузере были более свежие отметки, экспортируйте backup из v7 и импортируйте его в v8.
- Второй участник получает пустой профиль и те же справочные данные об университетах.

## Тестирование безопасности
- После входа первого участника сохраните новый GPA/заметку, перезагрузите страницу и проверьте сохранение.
- В отдельном приватном окне зайдите под вторым аккаунтом: там не должно быть чужих заметок, документов или GPA.
- Убедитесь, что прямой запрос по чужому `user_id` не возвращает данные — это должна блокировать RLS.
- Проверьте, что третий email не получает доступ.
- Проверьте выход, повторный вход, экспорт и импорт JSON, а также Supabase Security Advisors.

## Важные ограничения
- **Без настройки Supabase реальный вход и облачное сохранение не работают.** Не называйте систему полностью запущенной до интеграционных тестов.
- GitHub Pages и исходный каталог публичны. Защищены только личные записи в базе.
- Публичная история коммитов v7 может содержать старые личные данные: новая версия **не стирает Git-историю**.
- Никогда не добавляйте в публичный репозиторий паспорта, транскрипты, рекомендации, личные JSON backups или секретные API-ключи.
- Синхронизация использует last-write-wins; одновременное редактирование одного аккаунта в двух вкладках может перезаписать изменения.
